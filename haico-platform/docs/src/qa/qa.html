CEO & CAO

— decision, money, risk

Is this real software or a mock-up?

Real software with fictional data. Every button works — approvals route, payroll calculates, journals post, files attach. What's missing is the secure server, real sign-in and real data, which is the build step.

How long, and when do we see value?

130 working days. Alderbrook Holdings goes live first (Feb 19, 2027), then Ridgeline Timber (Mar 5), then Silver Lake Lodges + Northbay Seafoods (Mar 19). First real payroll: Apr 12, 2027, after two side-by-side runs.

What does it cost?

Three parts: the build team (1–2 developers for ~6 months), cloud hosting (an estimated CAD $300–800 a month at our size — to be quoted in step 1), and staff time from HR, payroll and finance leads (~1 day a week). No per-user licence fees for the platform itself.

What does it replace — and what does it save?

Paper/email approvals, spreadsheets for leave and banked OT, separate HR, payroll and AP tools. Savings come from one sign-in, approvals in minutes, no re-keying between payroll and the books, and a full audit trail. Confirm the systems we switch off in step 2.

What's the biggest risk?

Paying people wrong. That's why payroll uses CRA-certified formulas and only goes live after two pay runs match the old system to the cent — the old system stays as the safety net.

Who owns the code? What if the developer leaves?

Agree it in the contract: Alderbrook Group gets the source code (private repository), the right to change it, and documentation. Standard technology (TypeScript, PostgreSQL) means any competent team can maintain it. Step 9 hands admin to Alderbrook Group IT.

Is our data safe and in Canada?

Yes — hosted in a cloud region in Canada, encrypted in transit and at rest, Microsoft sign-in with MFA, role-based access, every action in an audit log. Built to BC PIPA; an independent security test runs before go-live.

Can it grow with us — new companies, new rules?

Yes. Four companies today; each record carries its company, so adding a fifth is a settings change. Approval limits, menus and wording change from Administration screens, without code.

The demo can also be shown as one company — Alderbrook Holdings with the same eight departments, people and approvals — chosen on its first page.

IT Manager — the technical questions

Front end, back end, data, security and operations. “Proposed” means the recommendation for the live build; the final choices are confirmed with IT in steps 1–2.

IT Manager

Front end

— what runs in the browser

FEWhat is the demo built with?

Plain JavaScript modules (no framework), HTML and CSS, compiled by a small build script into one self-contained page (~8.2 MB incl. sample data and how-to images). It runs in any modern browser with nothing installed.

FEWhat will the live front end be?

Proposed: the same screens moved to a TypeScript web app (React) served from the cloud over HTTPS. The browser only displays data and sends actions — nothing sensitive is stored on the device.

FEPhones and tablets? Offline for crews?

Layouts already adapt to phone width — approvals, timesheets and requests work on a phone browser. No native app; offline timesheet entry for camps with no signal is a phase-2 option.

FEBrowsers, accessibility, theming?

Current Chrome, Edge, Safari and Firefox. Keyboard and screen-reader labels on controls, light/dark themes, readable font sizes. A formal WCAG 2.1 AA check is part of testing.

Back end

— server, API, business rules

BEIs there a back end today?

Not a separate server — the demo runs its “server” rules inside the page. They're written as 162 actions, each one: check permission → validate → change data → write audit. That's exactly the shape of an API, so they port across rather than being redesigned.

BEProposed back-end stack?

Node.js + TypeScript API (same language as the front end, so rules are shared), PostgreSQL, encrypted object storage for attachments, a job queue for emails, reminders and bank files. Containerised, deployed to Azure Canada.

BEHow are permissions enforced?

On the server, for every action — never just by hiding buttons. 13 roles with grants (e.g. ap.approve), scoped to company. Menus already show only what the server would allow; the automated test checks every role against every page (176 routes).

BEAPIs and integrations?

Planned: a documented REST API (not in the demo). First connections: Microsoft 365 (sign-in, email), bank direct-deposit/EFT file (CPA-005), CRA payroll formulas, Excel/CSV import and export. Live bank feeds need a bank-data provider agreement.

BEHow do approvals and workflows work?

A rules table per request type (the supervisor first, then director level above a threshold; Finance processes it after). The engine resolves the next approver, notifies them, records each decision with comment, and posts results (e.g. bill → journal). Admins edit thresholds on screen.

BEHow is it tested?

Automated browser tests sign in as every role and click through every page and workflow — the full demo script (62 steps) runs end-to-end with zero errors. The live build adds unit tests, payroll checks against CRA's PDOC calculator, and a pen test.

Data, security & operations

DATAWhere does demo data go today?

Only into the presenter's browser storage — fictional people, nothing sent anywhere. Never type real names, SINs or pay into the demo or the Netlify copy.

DATAHow is the data modelled?

Every change is an event (who, what, when) applied to tables — so history and the audit log come for free. ~80 record types: employees, timesheets, pay runs, accounts, journals, bills, POs, projects, files.

DATAHow do we migrate our data?

From Excel/CSV exports of today's systems: staff, vendors, chart of accounts, opening balances, leave and banked OT, year-to-date pay. Two trial loads; totals must match the old books before go-live.

SECURITYSign-in, MFA, leavers?

Microsoft Entra ID (your Microsoft 365 accounts) single sign-on with MFA. Disable the account in Microsoft and access ends. Roles are assigned in the app by an administrator; every change is logged.

SECURITYSensitive fields — SIN, bank, pay?

Encrypted in the database and masked on screen (e.g. •••••2239). Pay and SIN visible only to HR/payroll roles. Files open only for roles that can see the record — AP files need AP access.

OPSBackups, uptime, disaster recovery?

Managed database with daily backups and point-in-time restore; files replicated within Canada. Monitoring and alerts; target 99.9% uptime; restore tested before go-live. Records kept 6+ years for CRA.

OPSPerformance and scale?

Sized for hundreds of users across four companies; indexed database queries and paged lists. A load test with a year of real-volume data is part of step 5.

OPSSupport and updates after go-live?

Agree a support plan (response times, a test environment, monthly updates). Releases go to a staging copy first; Alderbrook Group IT gets admin access, runbooks and the source repository.

Finance, HR & managers — and the honest gaps

What each department will ask, then the list of things the demo doesn't do yet — say these before someone else finds them.

FinanceHR & PayrollManagers

Finance

Does it replace our accounting system?

It covers the general ledger, AP, AR, banking and reconciliation, budgets, fixed assets, inter-company and month-end close for all four companies, with GST. Decide in step 2 whether it replaces the current package or feeds it.

How do bills, POs and payments flow?

Purchase order request → approval → printed PO → goods received → bill (with its invoice files) → 3-way match → approval → payment batch → one journal entry. Each step links to the next and is in the audit log.

Can anyone change a posted entry or a closed month?

No. Posted journals are reversed, not edited, and a closed period refuses back-dated entries. Who did what, and when, is always on record — auditors can be given view-only access.

Reports and exports?

Trial balance, P&L and balance sheet by company and group, budgets vs actual, project budget vs spent. Most lists download as Excel, PDF or CSV.

HR & Payroll

Is the payroll calculation CRA-correct?

Not in the demo — its tax figures are illustrative. The live build uses CRA-certified formulas (federal + BC, CPP/CPP2, EI) checked against CRA's PDOC, then two real pay runs side-by-side before switching.

T4s, ROEs, remittances?

T4 boxes build from posted pay runs; ROEs draft from end-of-employment; PD7A remittances are tracked to their due dates. In the demo these are produced for filing by hand (ROE Web, CRA) — electronic filing is a later step.

Who can see salaries and SINs?

HR and payroll roles only. Managers see their team's time, leave and reviews — not pay. Employees see their own pay statements, T4 and documents.

BC rules — overtime, stat holidays, banked time?

Daily and weekly overtime (1.5× after 8 h / 40 h, 2× after 12 h), stat holidays, and banked OT with an 8-hour daily limit are built in and shown on timesheets and balances. Settings are per company.

Department managers

How much extra work is this for me?

Less: one Approvals page for timesheets, time off, expenses, purchases and travel — approve with a note, from a phone. Hiring requests and new projects are one form each, with status you can see.

What if I'm away — who approves?

If you're on approved full-day time off when a request is sent, it also goes to your own manager — the first decision counts. A “delegate my approvals while I'm away” setting is on the build list (not in the demo).

Say it straight — what the demo does not do yet (all in the build plan)

  • No server, real sign-in or passwords — data stays in one browser
  • Payroll tax is illustrative, not CRA-certified
  • No direct-deposit (EFT/CPA-005) bank file yet
  • No electronic filing to CRA / Service Canada
  • Emails are simulated inside the app, not sent
  • No live bank feeds — statements are imported
  • No open API for other systems yet
  • Dollars (CAD) only; English only
  • No native phone app or offline mode
  • No approval delegation setting for holidays
